# Route Report Prompt

Use this prompt when answering with a combo route or route context. Keep the
report in the final response unless the user explicitly requests a saved file.

## Evidence Section

Every verified route report should include compact evidence for:

- loaded deck name and main/extra/side counts;
- fixed opening cards or current starting state;
- successful `resetGame`, `executeAction`, and relevant `simulateActions`
  results;
- executed action labels or indexes in order;
- checkpoints saved/restored while comparing branches;
- failed branches and why they were abandoned;
- pending decisions, replay warnings, or unresolved limitations.
- for adapted legacy combos: source type/status, old-versus-current deck
  differences, fixed-opening availability, non-portable bindings, and the first
  step that could not be mapped or executed;

## Report Boundaries

- Write "best verified route found so far" unless the relevant legal branches
  were actually explored and compared with tools.
- Do not write "optimal", "complete", "engine-tested", "actual playable route",
  or equivalent labels unless evidence proves that exact label.
- Do not include an unavailable card in an executed step. If a needed card is not
  in the loaded deck and was not generated by an engine result, mark the route
  invalid or hypothetical.
- If a report mentions hypothetical improvements, keep them in a clearly named
  hypothetical section and do not mix them into executed steps.

## Save And Export Semantics

- Do not call `saveArtifact` during normal work. Its
  availability is opt-in and an explicit user request is required.

- `saveArtifact({action:"route",...})` succeeding means the route report file was written after
  validation. It does not prove facts that the report itself does not evidence.
- `saveArtifact({action:"replay",...})` succeeding means a `.yrp`/`.yrp2` file was written from the
  current response history. It does not prove route completion by itself.
- If replay saving returns `pendingDecision` or warnings, state that the file
  reflects the current partial/pending history.
- If the host does not expose `saveArtifact`, apply the same
  evidence rules in the final answer or in the host's equivalent persistence
  mechanism.

## Route Context For Other AI Tools

- Prefer structured route context over prose-only summaries: starting resources,
  verified tool calls, route steps, final state, evidence labels, warnings, and
  unresolved assumptions.
- Preserve source labels such as `executed`, `simulated`, `checkpoint`, `parsed
  replay`, and `hypothetical` so downstream agents do not confuse them.
- Keep card names and action labels exactly as returned by tools when they are
  used as replay or engine evidence.
